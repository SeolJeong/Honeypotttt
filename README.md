# HoneyAI

Evasion-aware attribution of SSH attack sessions: is the actor a **human**, a
**script**, or an **AI agent** — even when the AI is deliberately imitating a human?

ICT3214 Security Analytics — Coursework 2 (group project).

## Project data

The canonical dataset lives in `data/` (generated by the team, spec-aligned):

- `dataset1_sessions.json` — 208 sessions, full interleaved command/response traces
- `dataset2_tabular_features.csv` — one row per session, ~20 aggregate features (XGBoost input)
- `dataset3_auth_noise.csv` — 1,000 Stage-1 auth brute-force records (noise filter)
- `dataset4_llm_sequences.jsonl` — interleaved-text sequences (QLoRA input)

Splits are leakage-safe: train participants (P001–P003) disjoint from test
(P004–P005); `llama3` and the `avoid_systematic_enumeration` / `combined` evasion
strategies are held out for testing (model-family- and strategy-disjoint).

## Build plan (part by part)

1. Foundation — adopt the team dataset *(done)*
2. Realistic responses — replace placeholder shell output with believable responses
3. Stage-1 auth-noise filter (`dataset3`)
4. Feature extraction (tabular)
5. Model 1 — XGBoost
6. Model 2 — sequence model (GRU/LSTM)
7. Model 3 — QLoRA fine-tuned LM (Colab GPU)
8. Evasion experiments — the headline comparison
9. Dashboard + wild-data integration

## Data collection

A live Cowrie SSH honeypot collects real attacker traffic as **unlabelled wild
data** (for distribution comparison, case studies and the demo — never training
accuracy). Parser + wild samples added in a later part.
